# i18n: English / Korean / Japanese / Chinese support

Status: approved design, not yet implemented.

## Goal

`tarot-web`'s UI and card content, and `tarot-reader`'s card data, are
readable in English, Korean, Japanese, and Chinese. A language selector in
`tarot-web`'s top bar switches everything — static UI chrome and any
currently-drawn cards — in place, with no redraw and no page reload. The
choice persists across visits.

## Non-goals

- `tarot-reader`'s CLI (`cli.py`, `text_formatter.py`) and REST API
  (`api/`) stay English-only. Only its `deck.json` data gains translated
  fields. Making the CLI/API themselves language-aware is explicitly out
  of scope for this effort.
- No new languages beyond en/ko/ja/zh.
- No per-user accounts or server-side state — this is a local, static app;
  "persistence" means `localStorage` only.

## Why `tarot-reader` is in scope at all

`tarot-web` never calls into `tarot-reader`'s Python layer — it only
fetches `tarot-reader/src/data/deck.json` directly (see both repos'
`CLAUDE.md`). Translated card names/meanings are card *data*, and
`deck.json` is explicitly designed (per `tarot-reader/CLAUDE.md`) to be
the single portable source any native client reads directly — so
translated card content belongs there, not duplicated into `tarot-web`.
UI chrome and spread/position labels (Past/Present/Future, the ten Celtic
Cross position names) are a different story: `tarot-web` already
reimplements spread *logic* locally in JS rather than calling
`tarot-reader`'s `core.py` (its own `CLAUDE.md` says so explicitly), so
those strings stay in `tarot-web` — moving them upstream wouldn't even
reach `tarot-web` without `tarot-web` also starting to depend on
`core.py`, which is a bigger change nobody asked for here.

## Data design

### `tarot-reader/src/data/deck.json` (shared card content)

Each of the 78 card entries gains one new, additive key. Existing keys
(`name`, `arcana`, `number`, `suit`, `upright`, `reversed`, `images`) are
untouched — this is purely additive:

```json
{
  "name": "The Fool",
  "arcana": "major",
  "number": 0,
  "suit": null,
  "upright": "New beginnings, innocence, spontaneity, free spirit",
  "reversed": "Recklessness, lack of direction, poor judgment, folly",
  "images": { "default": "images/default/the_fool.jpg", "abstraction": "images/abstraction/the_fool.svg" },
  "translations": {
    "ko": { "name": "...", "upright": "...", "reversed": "..." },
    "ja": { "name": "...", "upright": "...", "reversed": "..." },
    "zh": { "name": "...", "upright": "...", "reversed": "..." }
  }
}
```

**Backward compatibility, verified:** `tarot-reader/src/deck.py` builds
`MAJOR_ARCANA`/`MINOR_ARCANA` via an explicit dict comprehension that
only projects known keys (`name`, `number`, `upright`, `reversed`,
`images`). Any extra key on the raw JSON object — `translations` — is
silently dropped. Nothing in `core.py`, `api/`, `cli.py`, or the existing
test suite (`tests/test_core.py`, `test_deck.py`, `test_search.py`, etc.)
reads or asserts against the full raw dict, so this change cannot break
any existing `tarot-reader` consumer. Confirmed by reading `deck.py` and
grepping the test suite for schema-sensitive assertions.

English itself is not duplicated under `translations.en` — the existing
top-level `name`/`upright`/`reversed` already are the English text.

### `tarot-web/i18n/translations.json` (UI-only, new file)

No card content here anymore (that now comes from `deck.json`). Shape:

```json
{
  "en": {
    "title": "Tarot Web",
    "subtitle": "For entertainment purposes only.",
    "spreadLabel": "Spread",
    "spreads": { "single": "Single Card", "three": "Three-Card (Past / Present / Future)", "celtic": "Celtic Cross" },
    "draw": "Draw",
    "reset": "Reset",
    "orientation": { "Upright": "Upright", "Reversed": "Reversed" },
    "positions": {
      "three": [ {"label": "Past", "description": "..."}, ... 3 total ],
      "celtic": [ {"label": "Present Situation", "description": "..."}, ... 10 total ]
    }
  },
  "ko": { ... same shape ... },
  "ja": { ... },
  "zh": { ... }
}
```

This replaces the hardcoded English strings currently inline in
`SPREADS` (`app.js`) and scattered through `index.html`.

## State model and switching (`tarot-web/app.js`)

Today, a drawn card's *display* text (localized name/meaning) is baked in
at draw time inside `drawOne()`/`buildCardElement()`. For language
switching to update in-place without a redraw, the app needs to track the
*logical* reading separately from its rendered text:

- `drawOne()` stops resolving display text. It returns
  `{ englishName, orientation }` where `orientation` is the canonical key
  (`"Upright"`/`"Reversed"`), not yet translated.
- A module-level `currentReading = { spreadKey, cards: [...] } | null` is
  set by `renderSpread()` and cleared by `resetReading()`.
- A new `renderCardText(cardEl, card, lang)` (or equivalent) resolves
  display strings at render time: card name/meaning from
  `deck[card.englishName].translations[lang]` (falling back to the
  top-level English fields when `lang === "en"` or a translation is
  missing), orientation label from `translations.json[lang].orientation`.
- Changing `#language-select`: set `currentLanguage`, persist to
  `localStorage`, re-render all static UI text (title, subtitle, button
  labels, spread dropdown option text, position labels/descriptions for
  the *currently selected* spread), and — if `currentReading` is
  non-null — re-render each existing card's text in place via the same
  resolution function, without touching the DOM structure, without
  replaying the flip animation, and without reshuffling.
- `loadDeck()` is unchanged in shape (still fetches the same
  `deck.json`) — it just now carries a `translations` field per card that
  wasn't there before.

### Fallback behavior

If a card's `translations[lang]` is missing (shouldn't happen once
content is complete, but defensively): fall back to the English
top-level fields rather than showing `undefined`. Same for any missing
`translations.json[lang]` UI key — fall back to the `en` block.

## Persistence

`localStorage.getItem("tarot-web-lang")` on load, defaulting to `"en"` if
absent or not one of the four supported codes. Saved on every language
change. This is a per-viewer convenience (per the artifact/browser-storage
norms this app already follows informally) — never shared, never read by
anything server-side, since this is a static site.

## Testing plan

No browser is available in this working session (established earlier in
this project), so verification is two-layered, same pattern used for
every other feature built so far in this project:

1. **Structural (Node, automated by whoever implements this)**:
   - Every one of the 78 `deck.json` entries has a complete `translations`
     block for `ko`, `ja`, and `zh` (all three of `name`/`upright`/
     `reversed` present and non-empty).
   - `tarot-web/i18n/translations.json` has all four language blocks with
     identical key shape (same keys present in `en`, `ko`, `ja`, `zh` —
     catches a missed string in one language).
   - A dry-run of the switch logic (simulated, no DOM) confirms no
     lookup returns `undefined` for any card × language combination.
   - `tarot-reader`'s own test suite (`python -m unittest discover
     tests` / `pytest`) still passes unmodified after the `deck.json`
     change, confirming the additive-field backward-compatibility claim
     above in practice, not just by inspection.
2. **Manual browser pass (the user)**: switch languages with no reading
   on screen (title/buttons/dropdown update) and with a reading on screen
   (cards update in place, no redraw, no flip replay), for all three
   spread types, confirming no layout breakage from longer/shorter
   translated strings (Korean/Japanese/Chinese text lengths differ
   notably from English, which matters especially for the compact Celtic
   Cross card layout built earlier).

## Rollout sequence

This touches two separate git repositories with independent histories;
order matters:

1. **`tarot-reader`**: add the `translations` block to all 78 `deck.json`
   entries. Run its test suite. Commit and push to
   `https://github.com/zafrem/tarot-reader.git` on its own `main` branch.
2. **`tarot-web`**: bump the submodule pointer to the new `tarot-reader`
   commit (same `git -C tarot-reader checkout <sha>` + `git add
   tarot-reader` + commit pattern already used once in this project for
   the earlier deck-loading fix).
3. **`tarot-web`**: add `i18n/translations.json`, rewrite `SPREADS` in
   `app.js` to source its labels from it instead of hardcoding English,
   add the state-model/switching changes described above, wire
   `localStorage` persistence.
4. Structural verification (Node) for both repos' new data, then commit
   and push `tarot-web`'s changes, then deploy (push to `main` already
   auto-deploys via the existing GitHub Pages workflow) and ask the user
   to do the manual browser pass.

## Open risk

Writing ~700 translated strings (78 cards × 3 fields × 3 non-English
languages) plus the `translations.json` UI content is a large content
task, not just a code change. The implementation plan should account for
this as real effort, not a quick aside — likely worth splitting the
translation-writing work by language or by arcana group across parallel
subagents during implementation, decided at planning time.
